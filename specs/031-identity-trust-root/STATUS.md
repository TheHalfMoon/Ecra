## Frozen v1 decisions

### Identity / bootstrap

- Reuse ECR-001 `PrincipalRef`, `PrincipalId`, `IdentityAssertionRef`, `IdentityAssertionId`, `Actor`, and `ActorId`.
- Bootstrap creates an opaque **Ecra-local installation principal**. It does not claim external/legal/NIST identity proofing.
- `PrincipalId` is generated and never derived from OS username/email/display labels.
- Bootstrap is complete only after protected backend material + authenticated protected trust-state durable publish + authenticated reopen.
- Partial bootstrap yields typed `incomplete_bootstrap`; no silent second principal/root mint.

### Lifecycle authority

- `ProtectedTrustStateV1` is authoritative for enrollment/current key generation/retirement/revocation.
- Ordinary DB/file metadata is non-authoritative/rebuildable.
- Only authenticated protected state can produce `VerifiedTrustSnapshot` for validation/issuance.
- V1 does not claim universal monotonic rollback resistance against restoration of an older valid protected state plus equivalent authorized keystore state.

### Issuance

- No generic `issue(arbitrary_principal_id, ...)` API.
- `EnrolledPrincipalHandle` + current `VerifiedTrustSnapshot` create a non-serializable, process-local `IssuerSession` fixed to one principal/root/key.
- Caller may request actor/audience binding but cannot substitute the subject principal.
- V1 cannot mint arbitrary on-behalf-of principals.
- No ECR-031 IPC/network assertion-minting service exists.

### Cryptographic custody

- Canonical v1 assertion/protected-anchor signing algorithm: Ed25519.
- The software signing key is generated by production CSPRNG and stored only as native-backend-protected secret material.
- It may be materialized only for bounded signing inside redacted/zeroizing secret handling.
- Portable v1 does **not** claim Secure Enclave/hardware-backed/non-exportable signing.
- Protected envelopes use the frozen ChaCha20-Poly1305/HKDF-SHA-256 direction.
